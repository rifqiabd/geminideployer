Google Login & CBT Terdaftar

Satu backend Cloudflare Worker untuk guru dan siswa: guru mengelola kuiz miliknya, siswa mengikuti CBT berdasarkan email Google yang terdaftar.

Tanggal: 25 September 2026 Revisi: 26 September 2026 Target: ±30 siswa Auth: satu Worker Legacy: tetap public

01Ringkasan Keputusan

Keputusan produk dan arsitektur yang dipakai dalam rencana ini.

Satu backend

Auth, guru, siswa, kuiz, dan CBT tetap berada dalam satu Cloudflare Worker.

Google OAuth

Guru dan siswa login dengan provider yang sama, tetapi role dan scope berbeda.

Roster CBT

Semua Google dapat login, hanya email yang terdaftar yang boleh mengikuti CBT.

Milik guru

Guru mengelola assessment baru yang dibuat atau di-generate olehnya.

Legacy public

Kuiz lama tetap public dan tidak dipindahkan menjadi milik guru.

CBT ketat

Satu attempt, timer server, autosave, submit idempotent, dan hasil dikendalikan guru.

Kill switch

Mode baru default public. Assigned mode diaktifkan eksplisit per assessment, jadi satu kegagalan tidak menjatuhkan kuiz lain.

JWT terverifikasi

Verifikasi ID token memakai library jose, bukan implementasi sendiri. Session disimpan di D1 dan dapat dicabut.

02Tujuan & Batas Kerja

Fase pertama fokus pada fondasi yang aman tanpa membongkar seluruh aplikasi lama.

Tujuan

  1. Mengganti password statis dengan identitas Google yang diverifikasi server.
  2. Memberikan setiap guru akses ke kuiz miliknya tanpa akses ke kuiz guru lain.
  3. Memeriksa email siswa terhadap roster CBT di server.
  4. Membuat timer, identitas, attempt, dan submit tidak dapat dimanipulasi client.
  5. Menjaga link public dan aplikasi legacy tetap kompatibel.

Termasuk

  • OAuth authorization-code dengan state, nonce, dan PKCE.
  • Session server-side yang dapat dicabut serta role admin, teacher, student.
  • Ownership assessment baru dan namespace KV.
  • Roster email per assessment dan dua mode public/assigned.
  • D1 migration untuk auth, assessment, roster, attempt, dan draft.
  • Timer server, autosave ber-throttle, resume, expiry, dan submit idempotent.
  • UI login, pengaturan akses, laporan, dan tes auth/CBT.
  • Migration tooling: direktori migrations/ dan dua npm script.
  • Harness tes HTTP dengan mock KV dan mock D1.
  • Endpoint admin untuk manajemen role guru dan escape hatch bootstrap.

Tidak termasuk fase pertama

Proctoring kamera, billing multi-sekolah, pemindahan owner massal untuk kuiz lama, fitur berbagi antar guru, collaboration real-time, serta konversi aplikasi HTML/React lama menjadi CBT.

Multi-attempt untuk siswa (max_attempts di-constraint ke 1), dan Cron Trigger untuk menandai attempt expired. Expired dihitung lazy saat request.

04Arsitektur Target

Semua keputusan penting tetap berada di Worker; D1 menyimpan state, KV menyimpan konten.

Browser guru/siswa │ ▼ Cloudflare Worker (Hono) ├─ Google OAuth + session server-side ├─ Authorization guru/siswa ├─ Public quiz compatibility ├─ CBT attempt lifecycle └─ Server-side grading │ ├──────────────► D1 │ users · sessions · assessments │ roster · attempts · drafts │ └──────────────► KV legacy public content namespaced owner content

Prinsip auth

  • Browser tidak boleh memberikan email, role, score, deadline, atau status attempt sebagai sumber kebenaran.
  • Worker memverifikasi ID token Google, signature/JWKS, state, nonce, PKCE, dan claim.
  • Browser menerima session aplikasi yang opaque, bukan token Google mentah.

Prinsip ownership

  • Assessment baru selalu memiliki owner_user_id.
  • Guru hanya dapat mengubah assessment dengan owner yang sama; admin menjadi pengecualian.
  • Konten baru memakai prefix seperti owned:<owner_id>:<assessment_id>:<version>:....
  • Record legacy tanpa assessment D1 tetap dibaca dari key lama.

06Alur Google Login

Semua akun Google dapat login; otorisasi diberikan setelah identity dan roster diverifikasi.

Guru/admin

  1. Buka dashboard.
  2. Worker membuat state, nonce, dan PKCE.
  3. Google mengembalikan authorization code.
  4. Worker menukar code dan memverifikasi ID token/JWKS.
  5. Email harus cocok dengan policy guru/admin.
  6. Session dibuat dan dashboard menampilkan assessment milik user.

Siswa

  1. Buka link CBT.
  2. Worker mengarahkan login Google bila belum login.
  3. Email dicari pada assessment_students.
  4. Email tidak terdaftar mendapat akses ditolak.
  5. Email terdaftar membuat atau melanjutkan attempt.
  6. Identitas attempt berasal dari session server.

Kontrol akses

  • ADMIN_EMAILS dibaca dari env dan hanya menentukan role admin saat user pertama kali dibuat.
  • Escape hatch wajib ada, karena ADMIN_EMAILS yang salah akan mengunci semua orang dari dashboard: promote manual lewat wrangler d1 execute.
  • Admin dapat menambah email guru melalui panel internal.
  • Login Google tidak otomatis memberi role guru.
  • Role student tidak pernah ditulis dari client; roster adalah satu-satunya sumber kebenaran.
  • Email dinormalisasi lowercase dan dibandingkan persis.
  • Cookie session menggunakan HttpOnly, Secure, dan SameSite=Lax.

08Lifecycle CBT

Server adalah sumber kebenaran untuk waktu, status, identitas, dan hasil.

  1. Guru membuat assessment assigned dan menambah roster email.
  2. Guru mengatur duration, deadline, max attempts, dan release hasil.
  3. Siswa login Google dan lolos pemeriksaan roster.
  4. Worker membuat attempt dengan started_at dan expires_at.
  5. Browser menghitung countdown dari server time, bukan jam lokal.
  6. Answers di-autosave ke local cache setiap perubahan, dan ke D1 secara ber-throttle.
  7. Setiap request memeriksa session, attempt, deadline, dan revision.
  8. Conditional update memastikan submit hanya berhasil satu kali.
  9. Retry submit mengembalikan hasil yang sama tanpa record kedua.
  10. Setelah deadline, attempt expired dan jawaban terakhir hanya bisa difinalisasi dalam grace window 5 menit.
  11. Guru dapat membuka hasil setelah policy mengizinkan.

Throttle autosave

  • Debounce 3 detik setelah perubahan terakhir, plus flush saat blur, visibilitychange, dan pagehide. Bukan per keystroke.
  • Key draft lokal memuat attempt ID, bukan slug saja, sehingga draft lama tidak terbaca sebagai attempt sekarang.
  • Setiap flush mengirim revision monoton; revision lebih rendah diabaikan dan draft lokal di-merge.
  • Gagal jaringan memicu status di UI dan retry dengan backoff; draft lokal tetap sumber pemulihan.
  • Setelah submit sukses, localStorage dibersihkan di blok finally, bukan hanya di jalur sukses.
Tidak mempercayai client

Email, role, attempt number, score, deadline, dan status tidak pernah dipercaya dari request body atau browser clock. max_attempts di-constraint ke 1 pada fase pertama.

10Ownership Konten Baru

Global slug tetap untuk legacy; konten baru tidak boleh saling menimpa.

  • Assessment baru menyimpan owner_user_id dan content_prefix.
  • Deploy/generate baru menulis metadata D1 dan konten KV dengan prefix owner/assessment.
  • Guru tidak dapat mengakses atau mengubah assessment guru lain.
  • Slug global menjadi fallback khusus legacy public.
  • Transfer ownership dapat menjadi fase berikutnya; tidak diperlukan untuk MVP satu guru.
  • Media assessment baru memakai prefix yang memuat assessment ID. Key media:<slug>:<name> yang ada tidak diubah dan tetap dibaca untuk legacy.

Media pada mode assigned

GET /media/:slug/:name hari ini sengaja publik supaya halaman kuis siswa bisa meng-embed gambar. Pada mode assigned, route ini harus resolve slug ke assessment lebih dulu: assessment public atau slug legacy dilayani seperti sekarang, sedangkan assessment assigned memerlukan session yang lolos gate roster dan mengirim Cache-Control: private, no-store. Karena itu slug assigned sebaiknya tidak pernah memakai slug yang sudah pernah dipakai public.

11Hardening Wajib

Prasyarat sebelum assigned CBT boleh dipakai oleh siswa.

  1. Hapus static cookie authenticated_user di src/auth.ts.
  2. Hapus fallback password admin123 di index.ts:34 dan hapus route /api/login password bersama.
  3. Satukan semua pemeriksaan admin melalui middleware/session resolver baru. Kelima pembacaan cookie mentah di index.ts:277,559,1297,1347,1368 harus hilang.
  4. Validasi CORS, payload, email, ownership setiap request. Ganti app.use('/api/*', cors()) dengan allowlist ALLOWED_ORIGINS.
  5. Tambahkan token CSRF pada tiga form POST lama (/api/deploy, /api/delete, /api/app/update) atau ganti ke fetch dengan header custom.
  6. Validasi ukuran body JSON dan harden rate limit. Fail closed untuk endpoint auth saat KV error.
  7. Fail closed ketika grading atau parsing CBT gagal; fail-open hanya untuk legacy /api/save/:slug dan /api/submit/:slug.
  8. Kunci print/kunci pada assigned mode di index.ts:167-183. Tidak bergantung pada link di dashboard.
  9. Cegah guru A mengakses report/media/source/assessment/attempt guru B. Jadikan GET /media/:slug/:name mode-aware.
  10. Hapus apiKey plaintext dari GET /api/media/:slug/gen-config (media-routes.ts:252-267), paksa Cache-Control: no-store, dan pertimbangkan ubah ke POST-only.
  11. Escape semua nilai dinamis di halaman admin, roster, dan laporan.
  12. Tambahkan rate limit untuk endpoint public, /api/login, OAuth callback, dan endpoint attempt.

13Konfigurasi Deployment

Secret tidak boleh disimpan di repository atau ditulis di dokumen.

GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
SESSION_SECRET
ADMIN_EMAILS
ALLOWED_ORIGINS
APP_URL
  • GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET per environment; production dan staging memakai registration OAuth terpisah.
  • SESSION_SECRET untuk menandatangani cookie opaque session.
  • ADMIN_EMAILS hanya mem-bootstrap role admin saat user pertama dibuat, bukan grant permanen. Pastikan benar sebelum deploy, dan siapkan escape manual bila salah.
  • ALLOWED_ORIGINS menggantikan CORS wildcard untuk admin API.
  • APP_URL untuk callback dan redirect yang tidak menebak origin dari header.

Callback yang diharapkan adalah /auth/google/callback. Semua secret masuk lewat wrangler secret put atau .dev.vars yang gitignored, mengikuti bentuk .dev.vars.example.

Storage development

STORAGE memakai remote: true di kedua environment, jadi wrangler dev menulis ke KV production sementara D1 masih lokal. Data uji hanya lewat staging, dan db:migrate:local hanya untuk iterasi lokal.

14Pengujian

Validasi lokal harus dilakukan sebelum migration atau deploy remote.

npm test
npm run typecheck

Harness

tests/quiz.test.mjs sekarang hanya mengimpor modul pure, jadi route auth/CBT baru tidak punya jalur uji. Tambah harness di tests/helpers/ dengan mock KV dan mock D1 yang cukup untuk membuat app.fetch(request, env) berjalan, lalu pitakan sebagai entry kedua di suite yang sama.

Minimum test cases

  • State, nonce, PKCE, signature, issuer, audience, expiry, dan email_verified.
  • Session cookie HttpOnly + SameSite, logout mencabut, dan session kedaluwarsa ditolak.
  • Email Google di luar roster ditolak dari CBT dan tidak membuat attempt.
  • Guru A tidak dapat membaca, mengubah, atau menghapus assessment guru B (report, media, source, attempt).
  • Guru hanya melihat assessment miliknya di dashboard.
  • Role admin tidak naik dari client; hanya ADMIN_EMAILS dan endpoint admin.
  • Legacy public quiz tetap dapat dibuka dan disubmit, termasuk fail-open grading yang lama.
  • Assigned mode menolak ?print=1&kunci=1 dan media privat memakai Cache-Control: private.
  • Timer tidak reset setelah reload dan jam browser tidak dapat menggeser deadline.
  • Draft ditolak setelah submit atau setelah deadline, kecuali dalam grace window.
  • Revision monoton mencegah draft lama menimpa draft baru.
  • Dua submit bersamaan menghasilkan satu final attempt.
  • Retry submit mengembalikan hasil yang sama dan tidak menambah record.
  • Kunci jawaban tidak bocor pada assigned mode.
  • Body lebih dari 512 KB ditolak dan spec gagal parse menghasilkan 502, bukan skor kosong.
  • show_result = false mengembalikan 403, bukan hasil kosong.

15Acceptance Criteria & Milestone

Selesai bila seluruh alur berikut benar-benar teruji.

Guru

  • Login Google berhasil.
  • Dapat membuat dan mengelola assessment miliknya.
  • Dapat mengatur roster dan aturan CBT.
  • Tidak dapat mengakses assessment guru lain.

Siswa

  • Login Google berhasil.
  • Hanya email roster yang dapat mulai CBT.
  • Timer server dan autosave bekerja.
  • Submit ganda tidak menghasilkan nilai ganda.

Legacy

  • Link public lama tetap terbuka.
  • Public submit lama tetap kompatibel.
  • Report lama tetap dapat dibaca.
  • Mode baru default public, jadi satu kegagalan tidak menjatuhkan kuiz lain.

Tooling

  • Migration versioning jalan di lokal dan staging.
  • Test suite punya jalur HTTP dengan mock KV dan D1.
  • Semua test auth dan CBT lulus.

Rollout

  • Migration lokal dan staging lulus.
  • Uji dua guru dan 30 siswa di staging.
  • Secret production terpasang dan ADMIN_EMAILS sudah diverifikasi.
  • Deploy dilakukan setelah smoke test.

Rollback

  • Migration tidak menghapus app_records.
  • Assessment bisa diturunkan ke public atau dinonaktifkan per assessment.
  • Tidak ada langkah yang bergantung pada Cron Trigger, sehingga tidak ada timer yang harus dibatalkan saat rollback.
  • Perubahan mode dapat dianulikan tanpa deploy ulang.
