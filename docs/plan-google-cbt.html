Google Login & CBT Terdaftar

Satu backend Cloudflare Worker untuk guru dan siswa: guru mengelola kuiz miliknya, siswa mengikuti CBT berdasarkan email Google yang terdaftar.

Tanggal: 25 September 2026 Target: ±30 siswa Auth: satu Worker Legacy: tetap public

01Ringkasan Keputusan

Keputusan produk dan arsitektur yang dipakai dalam rencana ini.

Satu backend

Auth, guru, siswa, kuiz, dan CBT tetap berada dalam satu Cloudflare Worker.

Google OAuth

Guru dan siswa login dengan provider yang sama, tetapi role dan scope berbeda.

Roster CBT

Semua Google dapat login, hanya email yang terdaftar yang boleh mengikuti CBT.

Milik guru

Guru mengelola assessment baru yang dibuat atau di-generate olehnya.

Legacy public

Kuiz lama tetap public dan tidak dipindahkan menjadi milik guru.

CBT ketat

Satu attempt, timer server, autosave, submit idempotent, dan hasil dikendalikan guru.

02Tujuan & Batas Kerja

Fase pertama fokus pada fondasi yang aman tanpa membongkar seluruh aplikasi lama.

Tujuan

  1. Mengganti password statis dengan identitas Google yang diverifikasi server.
  2. Memberikan setiap guru akses ke kuiz miliknya tanpa akses ke kuiz guru lain.
  3. Memeriksa email siswa terhadap roster CBT di server.
  4. Membuat timer, identitas, attempt, dan submit tidak dapat dimanipulasi client.
  5. Menjaga link public dan aplikasi legacy tetap kompatibel.

Termasuk

  • OAuth authorization-code dengan state, nonce, dan PKCE.
  • Session server-side yang dapat dicabut serta role admin, teacher, student.
  • Ownership assessment baru dan namespace KV.
  • Roster email per assessment dan dua mode public/assigned.
  • D1 migration untuk auth, assessment, roster, attempt, dan draft.
  • Timer server, autosave, resume, expiry, dan submit idempotent.
  • UI login, pengaturan akses, laporan, dan tes auth/CBT.

Tidak termasuk fase pertama

Proctoring kamera, billing multi-sekolah, pemindahan owner massal untuk kuiz lama, fitur berbagi antar guru, collaboration real-time, serta konversi aplikasi HTML/React lama menjadi CBT.

04Arsitektur Target

Semua keputusan penting tetap berada di Worker; D1 menyimpan state, KV menyimpan konten.

Browser guru/siswa │ ▼ Cloudflare Worker (Hono) ├─ Google OAuth + session server-side ├─ Authorization guru/siswa ├─ Public quiz compatibility ├─ CBT attempt lifecycle └─ Server-side grading │ ├──────────────► D1 │ users · sessions · assessments │ roster · attempts · drafts │ └──────────────► KV legacy public content namespaced owner content

Prinsip auth

  • Browser tidak boleh memberikan email, role, score, deadline, atau status attempt sebagai sumber kebenaran.
  • Worker memverifikasi ID token Google, signature/JWKS, state, nonce, PKCE, dan claim.
  • Browser menerima session aplikasi yang opaque, bukan token Google mentah.

Prinsip ownership

  • Assessment baru selalu memiliki owner_user_id.
  • Guru hanya dapat mengubah assessment dengan owner yang sama; admin menjadi pengecualian.
  • Konten baru memakai prefix seperti owned:<owner_id>:<assessment_id>:<version>:....
  • Record legacy tanpa assessment D1 tetap dibaca dari key lama.

06Alur Google Login

Semua akun Google dapat login; otorisasi diberikan setelah identity dan roster diverifikasi.

Guru/admin

  1. Buka dashboard.
  2. Worker membuat state, nonce, dan PKCE.
  3. Google mengembalikan authorization code.
  4. Worker menukar code dan memverifikasi ID token/JWKS.
  5. Email harus cocok dengan policy guru/admin.
  6. Session dibuat dan dashboard menampilkan assessment milik user.

Siswa

  1. Buka link CBT.
  2. Worker mengarahkan login Google bila belum login.
  3. Email dicari pada assessment_students.
  4. Email tidak terdaftar mendapat akses ditolak.
  5. Email terdaftar membuat atau melanjutkan attempt.
  6. Identitas attempt berasal dari session server.

Kontrol akses

  • ADMIN_EMAILS menjadi bootstrap role admin.
  • Admin dapat menambah email guru melalui panel internal.
  • Login Google tidak otomatis memberi role guru.
  • Email dinormalisasi lowercase dan dibandingkan persis.
  • Cookie session menggunakan HttpOnly, Secure, dan SameSite=Lax.

08Lifecycle CBT

Server adalah sumber kebenaran untuk waktu, status, identitas, dan hasil.

  1. Guru membuat assessment assigned dan menambah roster email.
  2. Guru mengatur duration, deadline, max attempts, dan release hasil.
  3. Siswa login Google dan lolos pemeriksaan roster.
  4. Worker membuat attempt dengan started_at dan expires_at.
  5. Browser menghitung countdown dari server time, bukan jam lokal.
  6. Answers di-autosave ke local cache dan D1.
  7. Setiap request memeriksa session, attempt, deadline, dan revision.
  8. Conditional update memastikan submit hanya berhasil satu kali.
  9. Retry submit mengembalikan hasil yang sama tanpa record kedua.
  10. Setelah deadline, attempt expired dan tidak dapat diedit.
  11. Guru dapat membuka hasil setelah policy mengizinkan.
Tidak mempercayai client

Email, role, attempt number, score, deadline, dan status tidak pernah dipercaya dari request body atau browser clock.

09Perubahan Frontend

UI guru, student gate, dan kuis memakai state server yang sama.

Dashboard guru

File: src/index.ts. Ganti password dengan tombol Google, filter assessment milik user, dan tampilkan mode Public/CBT.

Editor

File: src/quiz-editor.ts dan public/vendor/quiz-editor.js. Tambahkan mode, durasi, deadline, max attempts, dan release hasil di luar QuizSpec.

Student gate

Link assigned menampilkan login Google. Email tidak roster mendapat halaman ditolak dan tidak membuat attempt.

Quiz page

File: src/quiz-page.ts dan public/vendor/quiz.css. Tambahkan timer, autosave status, retry, attempt ID, serta cleanup draft setelah submit.

  • Public quiz tetap mempertahankan flow lama.
  • Assigned CBT tidak menampilkan name field bebas sebagai identitas.
  • Kunci jawaban disembunyikan pada assigned mode sebelum policy guru.
  • Local storage hanya cache draft, bukan otorisasi attempt.

10Ownership Konten Baru

Global slug tetap untuk legacy; konten baru tidak boleh saling menimpa.

  • Assessment baru menyimpan owner_user_id dan content_prefix.
  • Deploy/generate baru menulis metadata D1 dan konten KV dengan prefix owner/assessment.
  • Guru tidak dapat mengakses atau mengubah assessment guru lain.
  • Slug global menjadi fallback khusus legacy public.
  • Transfer ownership dapat menjadi fase berikutnya; tidak diperlukan untuk MVP satu guru.

11Hardening Wajib

Prasyarat sebelum assigned CBT boleh dipakai oleh siswa.

  1. Hapus static cookie authenticated_user.
  2. Hapus fallback password admin123.
  3. Satukan pemeriksaan admin melalui middleware/session resolver.
  4. Validasi CORS, payload, email, dan ownership setiap request.
  5. Fail closed ketika grading atau parsing CBT gagal.
  6. Kunci print/kunci pada assigned mode.
  7. Cegah guru A mengakses report/media/source assessment guru B.
  8. Escape semua nilai dinamis di halaman admin.
  9. Tambahkan rate limit endpoint public dan OAuth callback.

12Fase Implementasi

Urutan implementasi agar perubahan tetap dapat divalidasi di tiap tahap.

Fase 0

Fondasi auth

Mulai
  • Session helper dan normalisasi user.
  • Google OAuth, state, nonce, PKCE, ID token/JWKS.
  • Ganti password login lama dan pasang secret.
  • Tambah tabel users dan auth_sessions.
Hasil: guru dapat login dan dashboard lama tetap hidup.
Fase 1

Ownership assessment

Milik
  • Tambah assessments dan owner lookup.
  • Namespace KV konten baru.
  • Batasi dashboard/mutations ke owner/admin.
  • Legacy public tetap fallback.
Hasil: guru hanya melihat dan mengelola kuiznya sendiri.
Fase 2

Roster dan access gate

  • Tambah assessment_students.
  • Tambah form roster dan validasi email.
  • Arahkan link assigned ke Google login.
  • Tolak email yang tidak terdaftar.
Hasil: hanya siswa terdaftar yang dapat memulai CBT.
Fase 3

Attempt lifecycle

  • Tambah quiz_attempts dan quiz_drafts.
  • Start/resume, duration, deadline, autosave, expiry.
  • Conditional submit dan idempotent retry.
  • Adaptasi grading, essay, dan reports.
Hasil: satu siswa memiliki satu attempt CBT canonical.
Fase 4

UI dan kompatibilitas

  • Login page, session state, timer, autosave UI.
  • Perbaiki localStorage retry/cleanup.
  • Pertahankan public legacy.
  • Filter dan pagination report.
Hasil: alur guru dan siswa berjalan end-to-end.
Fase 5

Validasi dan rollout

  • Migration lokal dan staging.
  • Google OAuth callback production/staging.
  • Uji dua guru dan 30 siswa.
  • Smoke test public legacy lalu deploy production.
Hasil: assigned CBT aktif bertahap setelah semua acceptance criteria lulus.

14Pengujian

Validasi lokal harus dilakukan sebelum migration atau deploy remote.

npm test
npm run typecheck

Minimum test cases

  • State, nonce, PKCE, signature, issuer, audience, expiry, dan email_verified.
  • Guru A tidak dapat membaca atau mengubah assessment guru B.
  • Legacy public quiz tetap dapat dibuka dan disubmit.
  • Email Google di luar roster ditolak dari CBT.
  • Guru hanya melihat assessment miliknya.
  • Timer tidak reset setelah reload dan jam browser tidak dapat menggeser deadline.
  • Draft ditolak setelah submit atau deadline.
  • Dua submit bersamaan menghasilkan satu final attempt.
  • Retry submit mengembalikan hasil yang sama.
  • Kunci jawaban tidak bocor pada assigned mode.

15Acceptance Criteria & Milestone

Selesai bila seluruh alur berikut benar-benar teruji.

Guru

  • Login Google berhasil.
  • Dapat membuat dan mengelola assessment miliknya.
  • Dapat mengatur roster dan aturan CBT.
  • Tidak dapat mengakses assessment guru lain.

Siswa

  • Login Google berhasil.
  • Hanya email roster yang dapat mulai CBT.
  • Timer server dan autosave bekerja.
  • Submit ganda tidak menghasilkan nilai ganda.

Legacy

  • Link public lama tetap terbuka.
  • Public submit lama tetap kompatibel.
  • Report lama tetap dapat dibaca.

Rollout

  • Migration lokal dan staging lulus.
  • Uji dua guru dan 30 siswa.
  • Secret production terpasang.
  • Deploy dilakukan setelah smoke test.
