Rencana Refaktor

Pemisahan index.ts
gemini-deployer

Pemecahan berkas src/index.ts (±2.000 baris) menjadi modul-modul kecil yang mengikuti pola registrar yang sudah ada — tanpa mengubah perilaku, tanpa build step, tanpa dependensi baru. Pemisahan frontend/backend yang menambah build step ditolak untuk proyek ini.

Status: Selesai dieksekusi 6 modul baru 0 dependensi baru dibuat 28 September 2026

1 Ringkasan Keputusan

Apa yang dilakukan, apa yang ditolak, dan apa yang tersisa dari keputusan ini.

  • src/index.ts saat ini ±1.700 baris dan menjadi satu-satunya berkas yang menabrak pola proyek: semua area fitur lain sudah memisahkan diri lewat fungsi registrar (media-routes.ts, quiz-editor.ts, quiz-essay.ts, guide.ts, tka-studio.ts), sedangkan index.ts menggabungkan wiring, dashboard, rekap, auth, dan aksi dalam satu berkas.
  • Pemecahan dilakukan hanya memindahkan kode, tanpa mengubah perilaku, tanpa mengubah rute, tanpa mengubah urutan middleware, dan tanpa menambah dependensi.
  • Pemisahan frontend/backend (SPA atau pre-build step) ditolak untuk proyek ini — alasannya di Bagian 2.
  • Kompromi opsional (Fase B): ekstrak JS/CSS inline dashboard ke public/vendor/, ikut pola quiz-editor.js dsb. Ini tahap terpisah dan boleh dilewati.
Prinsip yang dipegang

Kalau setelah pemecahan ada perubahan perilaku yang terlihat guru atau siswa, itu tanda pemecahan salah jalan — berhenti dan periksa, jangan lanjut menambal.

2 Kenapa Tidak Dipisah Frontend/Backend

Empat alasan yang membuat pemisahan total (SPA + build step) mahal dan berisiko untuk satu-sekolah ini.

Tolak

Menabrak aturan “tanpa build”

SPA memerlukan bundler; AGENTS.md melarang menambah build/CI tanpa permintaan eksplisit. Repository ini sengaja tidak punya build, formatter, maupun lint — menambah satu build step berarti menambah satu titik kegagalan yang harus dirawat.

Tolak

CSRF dan sesi menempel di rendering server

Token CSRF diinjeksi ke meta tag dan setiap form, halaman login vs dashboard dirender kondisional di server. Pindah ke SPA berarti merancang ulang seluruh alur auth (pra-sesi, cookie HMAC, verifikasi token), bukan sekadar memindahkan kode.

Tolak

Tidak ada jaring pengaman

Suite tes (tests/*.mjs) tidak menyentuh rute HTTP/KV/D1 sama sekali. Menulis ulang dashboard ±800 baris tanpa regresi tes berisiko tinggi dengan manfaat kecil — audiensnya guru satu sekolah, bukan produk multi-klien.

Sudah cukup

Pemisahan “frontend” sebenarnya sudah ada

public/vendor/quiz-editor.js, quiz-essay.js, tka-studio.js adalah shell server tipis + JS browser yang mengelola UI sendiri. Itu pemisahan yang cukup tanpa build step — arah Fase B di bawah memperluas pola ini ke dashboard, bukan menggantinya.

Catatan penempatan helper (beda dari draf awal)

  • Draf awal menyebut admin-guard.ts. Saat eksekusi, errorPage juga dibutuhkan lintas modul (actions.ts, auth-routes.ts), jadi errorPage + denyAdminRequest digabung ke admin-shared.ts.
  • GET /p/:slug tidak tercantum di draf awal; ditempatkan di public-app.ts agar records.ts tetap fokus pada data kiriman/rekap.
  • sanitizeSlug, uniqueSlug, saveApp tetap privat di actions.ts (hanya dipakai /api/deploy dan /api/app/update).

4 Jebakan yang Harus Dijaga

Lima hal yang paling sering bikin refactor “hanya memindahkan kode” berubah jadi perubahan perilaku.

Wajib

1. Urutan middleware CORS tidak boleh berubah

app.use('/api/save/*', ...), /api/submit/*, /media/* (publik, origin: '*') harus terdaftar sebelum app.use('/studio/*', adminCors) dan app.use('/api/*', adminCors). Kalau registrar baru memasang rute sebelum middleware publik, CORS bisa salah lapis.

Wajib

2. Semua registrar menerima app yang sama

Pola yang sudah dipakai registerMediaRoutes(app) dst.; berkas baru mengikuti pola yang persis sama (registerDashboardRoutes(app), registerAuthRoutes(app), registerActionRoutes(app)).

Wajib

3. Import berekstensi .ts

Berkas baru yang diimpor tes (kemungkinan admin-guard.ts bila diuji) harus pakai impor .ts eksplisit dan tidak boleh menyentuh Context di jalur yang diimpor Node. Pemecahan ini idealnya tidak menambah modul yang diimpor tes sama sekali.

Wajib

4. Template literal raksasa dipindah utuh

Dashboard dan rekap berisi HTML ±700 baris dalam satu template string; pindahkan utuh, jangan dipecah-percah saat memindahkan. Satu kurung template yang salah bisa membuat halaman tampil setengah tanpa error yang jelas.

Wajib

5. parseBody() di-cache per request

Perilaku CSRF (denyAdminRequest membaca body untuk token) bergantung pada caching body Hono; jangan ubah cara pembacaan body saat memindah — khususnya jangan mengganti c.req.parseBody() dengan await c.req.text() atau serupa.

5 Verifikasi

Karena tes otomatis tidak menjangkau rute HTTP, verifikasi dilakukan berlapis: cek otomatis, smoke test rute lewat app.request(), lalu smoke test manual staging.

Sudah dieksekusi — 17/17 lulus

npm run typecheck bersih, npm test (5 berkas) hijau, dan smoke test rute lewat app.request() (Bun + KV/D1 tiruan, tanpa network) lulus 17/17 — mencakup penyajian /p/:slug, simpan/alias kiriman, form login + pra-sesi, guard rekap & aksi, dua lapis CORS, login salah/benar, dan deploy ber-CSRF.

Tes hijau ≠ selesai

npm test dan npm run typecheck wajib tetap hijau, tapi keduanya tidak menyentuh rute sama sekali. Jangan menganggap pekerjaan selesai sebelum daftar smoke test di bawah dilewati satu per satu.

6 Fase B (Opsional, Terpisah): Ekstrak Aset Dashboard

Tanpa mengubah struktur rute — memangkas berkas dashboard drastis dengan mengikuti pola aset yang sudah ada.

📧 Ekstrak inline JS dashboard

±200 baris (showDetail, print modal, edit modal, filterApps, deep-link ?app=) menjadi public/vendor/dashboard.js.

🎨 Konsolidasi token desain

Variabel :root (--bg/--surface/--accent dll.) yang saat ini terduplikasi antara dashboard dan halaman rekap — kandidat: dipindah ke public/vendor/quiz.css atau berkas teacher.css baru.

Manfaat & perhatian

  • Manfaat: mengikuti pola aset yang sudah ada, memangkas index.ts/dashboard.ts drastis, tetap nol build step.
  • Perhatian: template dashboard menyuntik nilai dinamis (authCsrf, APPDATA) ke JS — setelah ekstraksi, nilai itu harus tetap tersedia ke dashboard.js lewat window.APPDATA / meta tag, pola yang sudah dipakai quiz-report.js.
Boleh dilewati

Fase B adalah pembersihan kosmetik yang berdiri sendiri. Kalau Fase A sudah dieksekusi dan smoke test-nya bersih, Fase B bisa dijalankan kapan saja — atau tidak sama sekali.
